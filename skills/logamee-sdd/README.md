# Logamee SDD

**让 Agent 按 SDD 方式推进软件项目开发与迭代。**

`logamee-sdd` 是一个面向软件项目的 Agent Skill。它把需求讨论、
需求简报、SPEC、Plan、Tasks、实现、测试、验收、版本基线和后续变更
放进同一套可持续推进的流程中。

## 这是什么

软件项目在首次开发、测试和版本迭代阶段，遇到的问题不一定都是代码
Bug。它可能属于实现缺陷、Plan 不完整、已有规格需要调整、新需求，或者
多个规格同时变化。

这个 Skill 会先读取当前项目文件和工作状态，再选择合适的推进模式：

- **Bootstrap**：项目还没有稳定 V1，需求和架构仍在快速变化。
- **首次开发主循环**：目标已经相对明确，需要形成正式 SPEC、Plan 并实现。
- **稳定版本变更**：项目已有基线，需要处理新需求、规格调整或多规格变更。
- **BugFix 小循环**：SPEC 和 Plan 正确，但实现没有满足既定行为。
- **混合变更**：同一版本同时包含 BugFix 和新增需求，统一进入版本级变更流程。

它不会只根据历史对话猜测项目状态，而是以当前项目文档、源码、测试和
工作记录为依据。

## 适用场景

可以在以下场景调用：

- 从需求讨论推进到 SPEC、Plan 和实现；
- 检查一个项目目前处于哪个 SDD 阶段；
- 判断测试发现的问题属于实现、Plan、SPEC 还是新目标；
- 处理开发阶段的 BugFix 小循环；
- 处理稳定版本中的新增需求和混合变更；
- 检查文档、实现、测试和版本基线是否一致。

## 快速开始

将本目录安装到 Agent 的 Skill 目录：

```bash
mkdir -p "${CODEX_HOME:-$HOME/.codex}/skills"
cp -R skills/logamee-sdd "${CODEX_HOME:-$HOME/.codex}/skills/"
```

如果你已经进入本 Skill 目录，也可以直接复制当前目录：

```bash
cp -R . "${CODEX_HOME:-$HOME/.codex}/skills/logamee-sdd/"
```

安装后，在项目对话中明确调用：

```text
使用 logamee-sdd，先检查当前项目处于哪个 SDD 阶段，
再从未完成的阶段继续。
```

```text
使用 logamee-sdd，评估这个测试问题属于实现 Bug、Plan 问题、
规格变更还是新增需求，并说明判断依据。
```

## 工作方式

Skill 启动后会：

1. 绑定当前项目目录，读取项目说明、SDD 文档、源码和测试；
2. 判断当前项目是否存在未完成的阶段或版本基线；
3. 根据项目状态选择 Bootstrap、首次开发、稳定版本变更或 BugFix；
4. 只读取当前阶段需要的参考资料；
5. 形成或更新对应的文档、任务和测试记录；
6. 执行可重复的客观测试，并明确区分已运行、未运行和待人工确认的部分。

当规格和计划已经明确、问题只是实现没有满足约定时，进入 BugFix 小循环，
不借机添加新功能或放宽原有约束。当目标或技术方案本身发生变化时，返回
对应的 SPEC 或 Plan，而不是把问题伪装成普通代码修复。

## 典型提示词

```text
使用 logamee-sdd，读取当前项目的 SDD 文档和源码，
告诉我现在处于哪个阶段，以及下一步应该形成什么产物。
```

```text
使用 logamee-sdd，把这个测试反馈登记为 Issue，
判断它应该走 BugFix 小循环、Plan 调整、SPEC 变更还是新增需求。
先说明判断，不要直接修改代码。
```

```text
使用 logamee-sdd，按照已经确认的修复路径实施这个 Issue，
完成后运行可重复测试，并报告哪些结果可以由你自行收尾，
哪些结果需要我人工确认。
```

## 目录内容

- `SKILL.md`：Agent 实际加载的入口、模式分流和共同规则。
- `references/`：主流程、变更、Bootstrap、访谈和项目目录约定。
- `agents/openai.yaml`：OpenAI/Codex 界面元数据。
- `evals/evals.json`：分流行为的回归提示词。

本 Skill 不附带可执行程序，也不要求安装特定 CLI。实施阶段能否操作项目，
取决于运行它的 Agent 是否具有对应的文件访问权限、工具权限和项目上下文。

## 与其他 Skill 的关系

`logamee-sdd` 负责软件项目的 SDD 推进，不替代项目本身的测试框架、构建
工具或版本控制系统。它可以和具体项目的开发、测试或领域 Skill 配合，
但应以当前项目已确认的 SPEC、Plan 和用户决策为准。
