# Grill Me Interview Protocol

本模块将 Matt Pocock 的 Grill Me / Grilling 访谈方式整合进 `logamee-sdd`，并应用教材中
“内部按决策树推进、对用户一次只展示一个问题”的约定。上游来源快照见
`upstream/grill-me/` 与 `upstream/grilling/`。

## 访谈方式

1. 先确定当前访谈阶段，例如目标用户、核心场景、范围、验收或技术约束。
2. 在内部维护决策树：已确定的答案解锁后续问题；先问当前阶段最关键、前置条件已明确的问题。
3. 每次只向用户提出一个决策问题，等待回答后再继续。不要把同一阶段的多个问题打包展示。
4. 事实由 Agent 读取项目文件、源码、测试或工具查证；只询问用户才能决定的产品目标、范围和偏好。
5. 收敛一个阶段后，简要整理已确认内容，再进入下一阶段。信息足够时停止追问。
6. 访谈记录是输入材料，不是交付物。需求访谈结束后，将结论整理进同一份 `brief.md`，
   由用户在正常需求讨论中修订；不额外生成重复的访谈报告或审核版简报。

## 提问准入检查

Grill Me 的目标是用最少的关键问题消除阻塞，不是把决策树上的所有分支都问完。每次准备
向用户提出问题前，必须依次检查：

1. 这个答案是否会实质改变当前版本的产品目标、范围、验收标准、关键约束或高风险方案？
2. 如果暂时没有答案，是否真的无法编写下一份文档、制定计划或继续实现？
3. 这个问题是否只能由用户决定，而不能根据既有答案、项目资料和常规默认值合理处理？

只有三个条件都成立时才提问。否则按以下方式处理：

- 可以合理推断：采用默认值，并在文档中明确记录假设。
- 不影响当前版本：移入 Backlog、待观察项或后续版本，不继续追问细节。
- 属于实现细节：留给 Plan 或实现阶段，由 Agent 依据项目约束决定。
- 用户明确说“第一版不考虑”“以后再说”或纠正了问题前提：立即关闭整个相关分支，
  不得换一种问法继续追问该分支的状态、交互或异常处理。

不要仅仅因为某个概念已经被提及，就继续追问它的按钮、标签、状态流转、修复方式和边界
情况。除非这些细节会阻塞当前版本或涉及不可接受的安全、合规和数据风险，否则先推进项目。

## 提问与选项规则

每一次提问都必须帮助用户做出具体决策，而不是把分析工作转交给用户：

1. 每个问题必须给出 2–4 个具体、互斥或边界清晰、可以直接选择的建议选项。
2. 将 Agent 判断最合适的选项放在第一位，明确标注“推荐”，并用一句话说明推荐依据。
3. 每个选项都用一句话说明它的结果或关键取舍，让用户知道选择会带来什么影响。
4. 选项必须结合已经读取的项目资料和用户此前的回答动态生成，不能机械复用通用模板。
5. 除给定选项外，始终允许用户回答自己的方案或对某个选项作修改。
6. “每次只问一个问题”指一次只处理一个决策点；该问题下面列出多个建议选项不算多个问题。
7. 禁止只问“你想怎么做”“需要哪些功能”“目标用户是谁”之类没有具体建议的裸问题。
8. 即使 Agent 缺少足够信息，也要根据现有上下文给出暂定选项，并清楚标出所依据的假设。

推荐格式：

```text
问题：首版应该优先服务哪类用户？

A. 独立研究者（推荐）——与当前单人写作流程最匹配，可以先验证核心编辑体验。
B. 小型研究团队——需要同步、权限和冲突处理，首版范围会明显扩大。
C. 高校课程用户——更重视模板、作业分发和教学管理，产品方向会有所不同。

请选择 A、B 或 C，也可以给出你的方案或修改其中一个选项。
```

如果存在明显推荐答案，不要假装所有选项同样合适；如果不存在明显优先级，则说明各方案适用的条件，
仍然给出一个基于当前信息的暂定推荐。

## 停止条件

- 关键决策树分支已回答，未决项已记录为明确假设或待确认事项。
- 目标、主要用户、首版范围和重要约束足以编写需求简报。
- 用户确认访谈阶段结束，或明确要求先按合理默认值继续。

每次收到用户回答后都必须重新执行停止检查。只要当前资料已经足以形成或更新本阶段文档，
就立即结束 Grill Me，整理结论并进入下一阶段；不得为了“问得更完整”继续扩展新的问题
分支，也不得把“等待用户主动叫停”当作停止机制。
